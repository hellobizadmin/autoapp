# 차근차근 — 심사 대응 설명서

> 후속 음성 구성: Pleos 공식 온디바이스 한국어 재생과 사용자 청취를 확인했습니다. 아래 기존 시연·검증 설명의 음성 미연동 상태는 이전 시점 기록입니다. 현재 상태와 속도 조절 제한은 [한국어 음성 구성](KOREAN_TTS_SETUP.md)을 참고하세요.


작성일: 2026-11-13. 사용자가 제공한 심사 기준 이미지의 차량특화성·창의성·기술 활용성·사업성에 대응한다. 배점과 평가 결과는 추정하지 않는다.

## 제출용 소개

차근차근은 차량 경고가 발생했을 때 운전 상황에 맞춰 의미와 다음 행동을 쉬운 한국어로 알려주는 차량 경고 통역 앱입니다. 핵심 대상은 차량 지식이 많지 않은 50~60대 운전자입니다. 주행 중에는 짧은 한 문장으로, 정차 후에는 상세 안내와 최대 두 개의 버튼으로 정보를 제공합니다. 경고가 없을 때는 조용히 대기하고, 길 안내는 운전자가 승인한 뒤에만 요청합니다.

현재 제출 가능한 구현은 Pleos 에뮬레이터에서 실행되는 시뮬레이션 데모입니다. 차량·주행 상태는 Fake 입력이며, 실제 마이크 인식과 내비 목적지 변경은 연결되지 않았습니다. 한국어 TTS가 없는 검증 환경에서는 음성이 나오지 않습니다. 차량 고장 진단이나 안전 운행 가능 여부를 판정하는 서비스로 소개하지 않습니다.

## 네 가지 평가 관점과 근거

| 관점 | 전달할 가치 | 현재 증거 | 아직 필요한 증거 |
|---|---|---|---|
| 차량특화성 | 같은 경고도 주행·정차·상태 불명에 따라 정보량과 조작을 달리함 | FR-04~06 화면, FR-14 화면 종료 후 서비스, UNKNOWN에서 상세·버튼 숨김 | 실제 차량 상태 입력 및 대상 디스플레이 가독성 검증 |
| 창의성 | 경고 용어 풀이에서 끝나지 않고 긴급도·다음 행동·승인 흐름까지 연결 | 긴급도 우선 표시, 중복 안내 억제, 승인 이전 내비 요청 0회 | 기존 차량 안내 대비 이해도와 판단 시간 비교; 시장 최초라고 주장하지 않음 |
| 기술 활용성 | 차량 데이터 → 규칙 판단 → 상황별 안내 → 승인 후 행동의 구조 | 순수 Kotlin 코어, Android 서비스, 40개 JVM 테스트 및 에뮬레이터 화면 시나리오 | Pleos SDK 실제 입력·음성·내비 연동. 에뮬레이터 실행을 SDK 연동 성과로 표현하지 않음 |
| 사업성 | 낯선 경고를 이해하기 어려운 운전자에게 필요한 순간의 도움 | 대상과 사용 시나리오 정의 | 사용자 인터뷰, 이용 의향, 도입 기관 수요와 비용 검증 |

## 대표 사용 시나리오

운전 중 타이어 경고가 발생한다. 운전자는 긴 설명이나 메뉴 조작 대신 위치와 다음 행동을 한 문장으로 확인한다. 정차하면 상세 설명을 읽거나 다시 듣고, 원할 때 정비소 안내를 승인한다. 같은 경고를 반복 수신해도 중복 안내하지 않는다. 상태를 확인할 수 없으면 정차로 추측하지 않는다.

이는 설계 시나리오이며 실제 사용자 사례나 실차 검증 결과가 아니다. 경고 문구·긴급도·거리 임계값은 제출 데모 기준이며 차량 취급설명서와 전문 검토를 거쳐야 한다.

## 사업성 가설과 검증 순서

- 1차 사용자: 차량 경고 해석에 어려움을 느끼는 50~60대 운전자. 연령만으로 어려움을 단정하지 않고 최근 경험과 이해도를 확인한다.
- 초기 제공 방식 가설: Pleos 호환 차량 앱으로 제공하고, 운전자 교육·차량 인도 안내 과정에서 체험 접점을 확보한다. 실제 배포 가능 여부와 협력사는 미확정이다.
- 구매자 가설: 개인 운전자 또는 차량 이용 경험을 개선하려는 렌터카·차량 운영 사업자. B2C 이용 의향과 B2B 도입 의향을 별도로 검증한다.
- 수익 모델 가설: 기본 경고 안내의 유료 구매 의향과 사업자 단위 제공의 타당성을 조사한다. 정비소 광고·유료 추천을 긴급도 판단에 연결하지 않는다. 가격·매출·제휴 성과는 아직 없다.
- 지속 이용: 경고가 없을 때 앱을 자주 열게 만드는 것이 목표가 아니다. 감시 유지 의향과 다음 경고에서도 다시 사용할 의향을 확인한다.
- 확대: 먼저 지원 차량·경고의 정확성과 접근성을 검증한다. 로그인·서버·예약·이력 저장 등 명세 9장 제외 기능은 이번 보완에 추가하지 않는다.

## 검증 지표 — 실적이 아닌 측정 계획

| 지표 | 정의 | 수집 방법 |
|---|---|---|
| 안내 이해도 | 위치·긴급도·다음 행동을 모두 바르게 설명한 과제 수 / 유효 과제 수 | 정답 기준을 사전 고정한 정차 상태 사용성 과제 |
| 판단 시간 | 안내 노출부터 다음 행동 선택까지 걸린 시간 | 동일 조건 비교, 중앙값과 범위를 함께 보고 |
| 오승인 | 동의하지 않았는데 길 안내가 실행된 건수 | 모호한 발화·취소·버튼 미입력 테스트, 성공 사례와 분리 |
| 재이용 의향 | 다음 경고에서도 사용하겠다는 응답과 그 이유 | 인터뷰 원문과 부정 의견 함께 기록 |
| 유지율 | 최초 활성화 코호트 중 30일 후 감시를 유지한 사용자 비율 | 향후 동의한 파일럿에서 측정, 현재 앱에 분석 서버 추가 안 함 |
| MAU | 월간 사용의 정의와 실제 활동을 분리해 집계 | 향후 파일럿에서 전면 이용자와 감시 활성 사용자를 구분, 현재 미측정 |

## 발표 구성 제안

1. 문제: 경고는 보이지만 의미와 다음 행동을 이해하기 어렵다는 가설.
2. 대상: 차량 지식이 많지 않은 50~60대 운전자와 검증할 실제 경험.
3. 해결: 주행 중 최소 안내 → 정차 상세 → 운전자 승인.
4. 증거: 화면 시연, 테스트 결과, 실제 연결과 시뮬레이션의 구분.
5. 실행 계획: SDK 연동 검증 → 정차 사용성 조사 → 허용된 환경에서 차량 검증.
